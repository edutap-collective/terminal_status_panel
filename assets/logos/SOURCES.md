# Logo provenance

Every `.ans` file bundled under `src/terminal_status_panel/render/logos/` is
listed here with the artwork it was generated from and the terms under which it
is redistributed. Marks belong to their respective owners; they appear in this
panel to state which operating system a machine runs, which is referential use
and not a claim of endorsement.

Regenerate the `.ans` files with `python tools/generate_logos.py`.

## Omitted marks

These keys are resolved by `_logo_name` (they degrade to an empty logo, per
`os_logo_by_key`, rather than to Tux — that fallback is reserved for Linux
distributions, and BSDs and RHEL-family systems already have no fallback in
the existing resolution table) but ship no artwork:

| Key | Reason |
| --- | --- |
| `rhel` | Restrictive by the trademark owner's own statement. Red Hat's trademark guidelines (<https://www.redhat.com/en/about/trademark-guidelines-and-policies>, fetched directly): "These Guidelines do not give you any permission to use a Red Hat Logo or any Red Hat Word Mark in a stylized form" without "a separate, express written agreement with Red Hat." Red Hat's brand standards page (<https://www.redhat.com/en/about/brand/standards/logo>, fetched directly) separately says: "Don't use legacy logos or Tux the penguin (the Linux® mascot), with or without the Red Hat logo." |
| `fedora` | **Could not verify — primary source unreachable.** `docs.fedoraproject.org/en-US/legal/trademarks/`, the `fedoraproject.org/wiki/Legal:Trademark_guidelines` redirect, a reader-mode proxy, and a PDF mirror were all tried; every attempt (including a direct `curl` with a browser user agent) was blocked by Fedora's "Anubis" anti-bot proof-of-work challenge, which serves an HTML/JS challenge page instead of content and cannot be solved with the tools available here. Third-party search summaries suggested a permissive "referential/fair use" clause, but I never read that clause myself, so per the "never record a licence you did not read" rule I am not shipping it or recording its terms as fact. |
| `alma` | Ambiguous fit. AlmaLinux's trademark usage policy (<https://almalinux.org/p/the-almalinux-os-trademark-usage-policy/>, fetched directly and read in full) enumerates specific acceptable uses — unmodified redistribution, the separate "Powered by AlmaLinux OS" badge for apps running on an official release, noncommercial decorative skins, and illustrations in books/articles/presentations. None of those categories clearly covers a persistent small status-icon identifying the detected OS in third-party software; the closest analogue ("Powered by AlmaLinux OS") is a distinct badge graphic, not the general logo. Ambiguous enough that I chose not to ship it. |
| `opensuse` | **Could not verify — primary source blocked.** `en.opensuse.org/openSUSE:Trademark_guidelines` returned HTTP 403 both via direct fetch and via a reader-mode proxy. A general web search (not a direct read) suggested "use of SUSE trademarks almost always requires written permission or a license," consistent with a restrictive policy, but I could not confirm the exact wording myself. |
| `suse` | **Could not verify — primary source blocked/truncated.** `brand.suse.com/suse-logo` loaded but was truncated before any third-party-use section; I found no complete statement of terms I could read and quote. |
| `freebsd` | **Legibility, not licence.** The FreeBSD Foundation's Trademark Usage Terms and Conditions (<https://freebsdfoundation.org/legal/trademark-usage-terms-and-conditions/>, fetched directly) actually permit this use: "Any individual, organization, or company may, without explicit permission from the Foundation, use the FreeBSD Marks to show support for the Project or as part of a notice to users that a product incorporates the FreeBSD operating system." The Foundation's official asset package (<https://freebsdfoundation.org/brand/>, "FreeBSD_Logo Set (Original Red)") only publishes combined wordmark + "FOUNDATION" lockups, no standalone icon, and the terms forbid altering the released artwork. Rendered at 18 character cells the wordmark is illegible and the icon reads as an indistinct red blob — worse than showing nothing. Dropped for that reason; the licence itself would have supported shipping it if a legible standalone icon existed. |

Any Linux distribution not listed above falls back to `linux.ans` (Tux) via
`_logo_name`; this is a true statement about the kernel even when the
distribution's own mark is not bundled.
